## 本机试用

入口仍为 https://127.0.0.1:18443 ，使用原试用实例账号。管理员随机密码的读取方式见 [TRIAL.md](TRIAL.md)。测试证书与数据库、附件卷沿用原实例。

UI 镜像单独标记为 `build-a-wiki-gateway:ui-refresh`，使用以下覆盖配置切换前端：

```bash
docker compose --env-file .data/compose-test.env -p wiki-acceptance \
  -f deploy/compose.yaml -f deploy/compose.ui-preview.yaml \
  up -d --no-deps --no-build --pull never gateway
```

回到原 `v0.1.0-rc1` 界面时，省略覆盖配置，仅重建 gateway 即可：

```bash
docker compose --env-file .data/compose-test.env -p wiki-acceptance \
  -f deploy/compose.yaml up -d --no-deps --no-build --pull never gateway
```

先前 `.data/releases/0.1.0-rc1` 离线包仍对应原候选版，未覆盖成新版 UI；当前 UI 改动、截图和验收记录另行提交 Git。本次视觉改版不替代 T59 的真实试用反馈或 T60 的正式发布交接。

## 修复展开目录时闪烁

修复前，每次展开会重新挂载子目录，以空数组开始渲染，网络响应到达前误显示“暂无可见页面”；延迟响应的专项测试已复现该空态闪现。目录出现/消失时，自动滚动条还会改变可用宽度。

现在仅在请求成功且确实为空时显示空态；首次加载使用固定行高的状态提示。分页数据按当前用户、知识库和父页面缓存，再次展开保留已加载行并后台校验，创建/删除/权限变更继续通过统一目录事件刷新。请求失败时隐藏旧行并显示重试入口，避免撤权后仍显示旧目录。祖先节点在初始状态展开，减少先收起再展开的中间布局。

侧栏通过 `scrollbar-gutter: stable` 预留滚动条宽度，真实溢出仍能滚动，并保留深层目录必要的横向滚动能力。本轮使用已有 React Query，无新增依赖。

新增 `e2e/tree.spec.ts`：人为延迟响应，验证首次加载不显示假空态、重复展开保留节点、临界高度下无瞬时溢出且宽度稳定、真实溢出时宽度不变且能滚动、撤权刷新后清除旧行。完整回归 5 项浏览器场景通过（59.2 秒）；8 项单元测试、格式检查及生产构建通过。最终镜像 ID 前缀 `d0eacc2c9bd3`。
最终 HTTPS 入口再次通过目录专项及部署登录检查（2 项，2.3 秒）；临时复现用前端服务已关闭，原试用服务继续运行。

## 修复切换功能页时目录闪烁

问题由路由地址参与知识库列表缓存键和 PageTree 组件 key 引起：切换“与我共享”“回收站”等页面时，列表进入新加载状态，原目录组件被卸载重建。新增复现测试确认旧节点在切换后断开 DOM。

知识库列表按用户缓存、页面详情按用户及页面 ID 缓存，目录组件仅按知识库 ID 标识。切换路由时保留目录节点与手动展开状态，同时后台重新校验导航数据；刷新报错时隐藏旧目录并提供重试，继续处理撤权后的可见性。

专项测试延迟子目录刷新响应，连续切换共享、回收站、服务状态，验证 DOM 节点持续存在、展开状态和宽度/溢出指标稳定，并保留撤权刷新检查。四项浏览器回归通过（35.3 秒，含正常/减少动态效果、目录与响应式 UI），生产构建通过。本地镜像 `947d6e229b74`，无新增依赖。
