# 单人 / 单 Agent 开发任务规划

依据：[WIKI_DESIGN.md](./WIKI_DESIGN.md) · 版本：v0.1 · 日期：2026-11-16

## 1. 如何执行

下表行号就是建议执行次序，是任务依赖 DAG 的一种拓扑排序。依赖栏只记录直接前置任务，间接依赖沿链条追溯。没有依赖关系的任务也被排成顺序，目的是方便单个开发者执行，不表示它们存在技术上的先后约束。拓扑排序不是唯一解，也不代表已计算工期或关键路径。

首版执行 T01—T60；后续扩展 E01—E20 单独排队，不阻塞首版发布。所有任务初始状态均为待开始。本规划只拆任务，不代表已经完成开发。

每次只推进一个任务；开始前检查依赖的完成证据，完成后提交代码、更新任务记录，再进入下一项。任务包含自己的校验，不把全部测试推迟到最后。建议每项对应一个可独立评审的提交或小型提交组；若范围仍过大，在原 ID 下拆子任务并保留依赖。

统一完成条件：实现与契约一致、对应校验通过、相关文档更新、没有隐藏的占位实现。测试失败时当前任务仍未完成，修复属于本任务，不创建指向过去节点的循环依赖。

## 2. 必须先落实的设计细节

现有设计足以拆解任务，但以下细节必须在 T01—T03 固定，避免实现中反复改动：

- 组成员撤销和正文保存之间的并发语义：撤权事务提交后发起的新操作必须被拒；已经在执行的操作按统一锁顺序串行化。
- 建库所有者停用、转让、最后一个系统管理员保护，以及管理员重置密码时的会话失效规则。
- 页面移动必须检查源页面管理权限和目标位置的接纳权限；删除子树是否要求管理每个独立授权后代。建议首版要求完整子树管理权限，否则拒绝整个操作。
- 删除、移动预览也须鉴权，不能用“受影响数量”泄露不可见子树。
- 正文 schema、标题是否进入版本、版本恢复是否恢复标题。建议标题与正文共同版本化，恢复时一起恢复。
- “最近访问”、草稿 GET/DELETE、账号与组管理、所有权转让等功能补齐数据表和 API；原设计中的接口表并非完整接口清单。
- 知识库归档/删除、附件手动删除、配额等未明确操作不默认扩展范围；如加入，先补需求和验收任务。

## 6. 单 Agent 工作记录模板

```text
任务 ID：Txx
状态：待开始 / 进行中 / 阻塞 / 完成
直接依赖及证据：
本次目标：
涉及文件与迁移：
实现记录：
执行的校验及结果：
未解决问题：
提交或产物位置：
下一项任务：
```

不把“写了代码”“页面能打开”当作复杂权限任务的完成证据。暂停时记录运行服务、测试库和未提交变更，后续 agent 可以从任务记录继续，无需重新猜测状态。

## 7. 依赖排序校验方法

对任务表提取所有 ID 和依赖；检查 ID 唯一、依赖存在、自依赖不存在，且每项依赖在当前排序中的位置严格小于本任务。该条件成立即可证明给出的线性顺序是合法拓扑序，同时排除环。它不证明任务拆分已经穷尽所有实现细节；需求变化后仍需补充任务和依赖。

本稿不提供固定人日估计：单人熟练度和 agent 的工具/测试环境差异很大。完成 T12 后可根据真实速度估算剩余工作；单执行者的总工期按实际顺序累计，不能使用并行团队的关键路径时长替代。
